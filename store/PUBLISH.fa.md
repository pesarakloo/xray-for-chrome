# راهنمای انتشار 0.7.4

این بسته برای بارگذاری و بررسی در Chrome Web Store آماده شده است؛ هنوز منتشر یا توسط Google تأیید نشده است. تأیید نصب و اتصال روی دستگاه واقعی و تصاویر واقعی رابط کاربری باید پیش از Submit انجام شود.

| --- | --- |
| سورس GitHub و دریافت برنامه مکمل | محتویات پوشه اصلی xray-for-chrome |

## مراحل به ترتیب

1. فایل‌های پروژه را در مخزن خود قرار دهید و بسته کامل را در یک Release بارگذاری کنید. مطمئن شوید لینک Releases و فایل PRIVACY.md بدون ورود به حساب باز می‌شوند. مسیر پیشنهادی سیاست پس از انتشار فایل: https://github.com/pesarakloo/xray-for-chrome/blob/main/PRIVACY.md . این نشانی تا زمانی که فایل را واقعاً منتشر نکرده‌اید آماده نیست.
2. وارد https://chrome.google.com/webstore/devconsole شوید. ثبت‌نام ناشر، ایمیل تأییدشده و تأیید دومرحله‌ای حساب را تکمیل کنید. وضعیت و هزینه احتمالی ثبت‌نام را در همان داشبورد ببینید.
3. روی New item بزنید و فقط release/chrome-web-store-v0.7.4.zip را بارگذاری کنید. manifest.json در ریشه همین ZIP است. ZIP کامل پروژه را در استور بارگذاری نکنید.
4. شناسه‌ای که داشبورد برای آیتم می‌سازد شناسه نسخه رسمی است. کلید نسخه دستی فقط شناسه توسعه را ثابت نگه می‌دارد و تضمین نمی‌کند استور همان شناسه را بدهد. کلید نسخه دستی در بسته استور حذف شده است؛ برای به‌روزرسانی دستی کاربران قبلی، کلید پوشه extension حفظ شده است.
5. نسخه استور را ابتدا با روش آزمایش خصوصی/Trusted testers داشبورد، یا نسخه آزمایشی دارای public key همان آیتم، بررسی کنید. در تب آموزش، دستور نصب را کپی کنید؛ شناسه واقعی افزونه خودکار در آن درج می‌شود. آن را در پوشه بسته کامل اجرا کنید. Windows پارامتر -ExtensionId و macOS گزینه --extension-id را می‌پذیرند. برنامه مکمل فقط شناسه دستی و شناسه صریح داده‌شده را مجاز می‌کند؛ هیچ wildcard استفاده نشده است.
6. از store/LISTING.md متن فارسی و انگلیسی، هدف واحد و دلیل مجوزها را وارد کنید. فارسی پیش‌فرض رابط برنامه است؛ زبان اصلی صفحه استور را هم فارسی انتخاب و ترجمه انگلیسی را اضافه کنید. نام و توضیح استور باید نیاز به نصب برنامه مکمل و کانفیگ شخصی را روشن بگوید.
7. در Privacy practices، URL عمومی سیاست را وارد کنید. «هیچ داده‌ای نداریم» را کورکورانه انتخاب نکنید: برنامه اطلاعات احراز هویت و URL اشتراک را محلی پردازش می‌کند و ترافیک از سرور انتخابی کاربر عبور می‌کند. جدول داده‌ها و توضیح ارتباط‌های شبکه در LISTING و PRIVACY را با سؤال‌های همان فرم تطبیق دهید. برای JavaScript افزونه از کد راه دور استفاده نمی‌شود؛ برنامه مکمل جداگانه و دریافت Xray توسط نصب‌کننده را در یادداشت بررسی صریحاً توضیح دهید.
8. آیکون و تصویر تبلیغاتی آماده را اضافه کنید. حداقل یک اسکرین‌شات واقعی از همین نسخه لازم است؛ ترجیحاً تصاویر صفحه اتصال، مدیریت و راهنما در هر زبان. اندازه اعلام‌شده Chrome برای اسکرین‌شات 1280×800 یا 640×400 است. از نمایش رمز، URL اشتراک یا سرور شخصی خودداری کنید. تصویر تبلیغاتی، جای اسکرین‌شات واقعی را نمی‌گیرد.
9. مراحل آزمایش زیر را روی Windows و macOS انجام دهید، نسخه هسته و نتیجه را ثبت کنید و خطاهای باقی‌مانده را برطرف کنید. برای بررسی Google یک کانفیگ معتبر مخصوص بررسی با دسترسی محدود و قابل تمدید، در بخش خصوصی راهنمای بررسی آماده کنید؛ هیچ رمز یا لینک اشتراکی را در سورس یا توضیح عمومی قرار ندهید.
10. بررسی نهایی فرم‌ها، تصاویر و لینک دریافت برنامه مکمل را انجام دهید و سپس Submit for review را بزنید. پذیرش و زمان بررسی در اختیار Google است. انتشار GitHub به‌تنهایی افزونه را در Chrome Web Store منتشر نمی‌کند.

## آزمایش پیش از Submit

- Windows PowerShell 5.1: نصب از ZIP دانلودشده، در مسیری دارای فاصله و حروف فارسی؛ حالت نصب تازه، نصب مجدد با حفظ هسته و نصب با -XrayExe؛ سپس حذف با uninstall-windows.cmd. به اجرای Administrator نیاز نباشد.
- macOS: نصب روی Intel و Apple Silicon، ثبت شناسه نسخه استور، اجرای هسته و حذف. امضای ad-hoc موجود در نصب‌کننده مک به معنی Apple Developer ID یا notarization نیست.
- نسخه دستی و نسخه استور: نمایش موتور، یک اتصال واقعی، قطع اتصال و بازگردانی پراکسی؛ نبود برنامه مکمل و نبود مجوز پراکسی باید پیام روشن بدهد.
- زبان: اولین اجرا فارسی، تغییر به انگلیسی و LTR، بازکردن مجدد با زبان ذخیره‌شده؛ تغییر زبان هنگام اتصال یا تست، نباید اتصال یا کانفیگ را عوض کند.
- سابسکریپشن: رد مجوز دامنه، پذیرش مجوز، دریافت و به‌روزرسانی HTTPS، خطای HTTP و تغییر مسیر؛ ورود دستی باید بدون مجوز سایت کار کند.
- پینگ HTTPS: تست تکی و همه، توقف صف، کانفیگ نامعتبر و سرور بی‌پاسخ؛ اتصال فعال تغییر نکند.
- پروتکل‌ها: با کانفیگ‌های واقعی مورد ادعای صفحه استور آزمایش کنید. Parser و تست واحد جای تست هسته را نمی‌گیرند. سازگاری Trojan و همه گزینه‌های پیشرفته با هسته Windows v25.8.3 در این محیط تأیید نشده است؛ پیش از ادعای پشتیبانی کامل آزمایش لازم است.

در این محیط  اجرای واقعی Windows، macOS و تصویربرداری از Chrome در دسترس نبوده است. نتیجه تست‌های انجام‌شده در VALIDATION.md ثبت می‌شود. گردش‌کار GitHub در .github/workflows/check.yml تست‌های سورس و کامپایل/راه‌انداز Windows را پس از push اجرا می‌کند؛ فایل‌های آن ساخته شده‌اند اما نتیجه CI هنوز موجود نیست.

## مسدودی دانلود و امضای انتشار

Windows ممکن است روی فایل استخراج‌شده از ZIP اینترنتی Zone.Identifier قرار دهد. RemoteSigned برای چنین PS1 بدون امضا خطا می‌دهد. راه‌اندازهای CMD همین بسته، فقط PS1 مشخص خودشان را Unblock کرده و با RemoteSigned اجرا می‌کنند. هیچ Set-ExecutionPolicy دائمی، خاموش‌کردن Defender یا دورزدن سیاست سازمانی وجود ندارد. خود CMD نیز ممکن است هشدار دانلود Windows بگیرد.

برای انتشار با هویت ناشر معتبر، گواهی Code Signing مورد اعتماد و امضای Authenticode با timestamp لازم است. گواهی و کلید خصوصی ناشر در این پروژه وجود ندارد؛ فایل‌ها امضاشده معرفی نشده‌اند. تغییر پسوند به EXE یا استفاده از گواهی self-signed به‌تنهایی اعتماد عمومی ایجاد نمی‌کند. حتی امضای معتبر تضمین حذف همه هشدارهای SmartScreen یا محدودیت سازمانی نیست. کلید خصوصی را هرگز در GitHub قرار ندهید.
